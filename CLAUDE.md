# GUNHOLLOW — project notes

Two HTML5 games in one project, both Phaser 3.80.1 from CDN with Arcade physics, both plain `<script>` tags with no build step.

| Folder | Game | Global namespace |
|---|---|---|
| `hollow/` | Hollow Knight style: sword, dash, wall-jump, benches | `GH` |
| `contra/` | Contra style run-and-gun "COMMANDO": seven agents with abilities, hearts + shared team lives, shop, cover, 1-5 local players + bots, Google sign-in, parties, queue, online co-op | `CG` |

`index.html` at the root IS COMMANDO's page: it has `<base href="contra/">`, so every relative path loads from `contra/` while the address stays `https://redfire3248.github.io/Commando/` (the user wants no `/contra/` in the URL). Edit the game's HTML there; `contra/index.html` only redirects to `../` (keeping `?guest&fakedb`). The GitHub repo is `Redfire3248/Commando` (renamed from GUNHOLLOW). HOLLOW is separate at `/hollow/`. `server/dev-server.js` serves the root; games live at `/hollow/` and `/contra/`. Each game is self-contained (own `assets/`, own `tools/build_art.py`, own generated `art.gen.js`). Nothing is shared between them on purpose.

## COMMANDO (`contra/`)

- `src/level.js` holds the stages as data in `CG.DATA.levels` (theme, ground pieces, ledges, enemy and capsule spawns, boss type); the Game scene points `CG.DATA.level` at the one being played and cycles through them, harder each lap. `CG.Level.check()` warns about enemies placed with nothing under them. Themes `jungle`, `base`, `snow` (`THEMES` in `src/art.js`); terrain/background textures are keyed `<name>_<theme>`. Bosses: fortress (cannons + core), tank, gunship (`final: true` clears the stage). Falling projectiles live in `scene.ebombs`. `src/sfx.js` synthesises all sound.
- **Season 2 (agents):** `src/agents.js` defines five agents (`CG.AGENTS`: razor, nova, kite, brick, volt) — hp, speed, one ability each (Bullet Storm, Mend, Phase Dash, Aegis, Chain Arc). Everyone carries the SAME rifle (the user does not want different weapons). Players have hearts (bullet 1, bomb 2, water = death) and the team shares one pool of lives (`scene.teamLives`, 3 + 2 per extra player); with none left a fallen player is out until the stage ends. Pick-ups: `heal` (+2, dropped by soldiers), `heal_big` (whole team), `life` (+1 team life), rapid, spread, barrier. Nametags + health bars float over players; the HUD shows portrait, hearts and the ability cooldown.
- **Season 3:** seven agents — the five pixel-art ones plus JAX (Frag Grenade) and DUKE (Adrenaline), the two original painted commandos (`classic: true`, art from `commandos.png`). Abilities got stronger (Storm pierces, Mend revives + brief invulnerability, Dash kill halves cooldown, Aegis reflects shots and covers teammates, Chain Arc stuns) and call out their name. Stages have NO pits any more (`CG.Level.noPits()`); instead `CG.Level.covers(L)` places solid cover (painted pieces from `contra/assets/cover50.png` → `cv50_<cell>`, per-theme sets in `COVER_SETS` of `build_art.py` → `CG.DATA.art.cover50[theme]`, cycled with a step of 7; the code-drawn `cv_*` boxes in `src/art.js` are the fallback) that stops every bullet and can be stood on — identical on every screen online, never destroyed. The painted near background strip and the painted floor props are gone (they looked like things sliding on the floor). Every stage now uses a full scene from `backgrounds15.png` (`bg15_1..15`, see `BG15` in `src/scenes.js`; the next scene is used each time the stages repeat).
- Accounts (season 3): signing in with Google is REQUIRED to play (offline only when Firebase is not set up or unreachable; `?guest` on localhost for testing). First sign-in asks for a unique callsign (`usernames/{lower}`); friends can be added by code or callsign. Coins (`users/{uid}/coins`, +1 per 40 points, not after admin use) buy shop items (`src/shop.js`; list in `shop/items`, defaults in `CG.Shop.DEFAULTS`; perks are applied to this device's account holder in `GameScene.create`). The admin panel (`src/admin.js`, **F2**) opens only for `redjai1981@gmail.com` (`CG.Net.ADMIN_EMAILS`; the database rules in `FIREBASE.md` also hard-code it) — tabs Players, Enemies, Items, Stage (mark the run), Shop (edit items live), Accounts (coins). Menus were redesigned (home screen with an agent showcase, settings, shop). Touch controls: floating joystick or D-pad (Settings), every finger tracked separately and able to slide between buttons, auto fire, three sizes, SKILL shows its cooldown; options in `CG.Touch.opts` (localStorage `commando.touch`).
- Agents are bought: RAZOR, JAX and DUKE are free (`CG.Shop.FREE_AGENTS`); KITE, NOVA, BRICK and VOLT are shop items of kind `agent` (`CG.Shop.AGENT_ITEMS`, always merged into the list; the admin can change their prices). `CG.Shop.hasAgent(id)` decides what this account may pick (everything when offline); bots may use any agent. The agent select screen is a full-screen layout (big portrait + stats + ability + LOCK IN / UNLOCK button, tiles underneath; tap a tile to look, tap again or the button to lock). COMMANDO ledges are solid on every side (hitbox as thick as the ledge art); Down + Jump still drops off one.
- Parkour layout (`CG.Level.parkour()` in `src/level.js`): each stage is rebuilt as alternating FIGHT zones (open ground, two pieces of breakable cover, nothing overhead) and CLIMB sections (`CG.Level.CLIMBS`: up-and-over, zigzag, high stepping stones) with coins up high (`L.coins`, +5 coins each for that account, `scene.coinsEarned`, paid out at game over); enemies from the old ledges move onto the nearest new ledge or the ground. Everyone has a double jump. Cover is breakable (`hitCover`/`breakCover`, hp from its height; online the host counts damage, clients send `cover` events, snapshot `cb` lists broken ones). Pick-ups pop up, land and float in place. Bullet power-ups from capsules: `pierce` (P), `blast` (X), `double` (D), `ice` (I); the admin-only `overdrive` (15 s untouchable + storm + adrenaline) is only in the admin Items tab. The admin panel's markup is created by `src/admin.js` only for the admin (it is not in `index.html`). Prompts 12 (four more agents: Ghost, Hammer, Viper, Atlas) and 13 (power-up badges) are waiting for art.
- 1v1 DUEL (`cfg.mode === 'duel'`, `scene.pvp`): arenas in `CG.DATA.arenas` (one screen, `spawnCols`, no boss: `boss.type 'none'`, wall skipped), first to `CG.DUEL_KILLS` (5). Bullets hit the other player (each game decides hits on its own soldier; `lastHitBy` gives the kill), abilities hit players via `damagePlayer` (online: `phit` broadcast), deaths go to `pvpDeath` → `countKill` (host/offline) or a `kill` event; snapshot carries `kd`/`win`. Local: lobby mode switch (alone = vs a bot; bots fight the other player in `bots.js duel()`). Online: squad of 2 → DUEL YOUR FRIEND, or FIND A DUEL (`CG.Queue.join('duel')` pairs two single players). Power-ups drop from the sky every 9 s. Everyone has a Tac Dash (Shift/V, T, I, pad B/LB, DASH button; 3.2 s cooldown, once in the air). Desktop ability slot sits top-right (`buildAbilitySlots`); on phones the SKILL button shows the ability icon + cooldown (`CG.Touch.setAbility/cooldown`). Touch controls default to a floating 4-way D-pad (appears under the thumb) with a coloured FIRE/JUMP/SKILL/DASH cluster. Admin Hacks tab: auto aim, strafe, speed, super jump, one shot, infinite dash, low gravity (`player.hack`).
- Flow (`src/ui.js`): login (Google) → menu → PLAY (local join screen, + bots) → agent select (each agent once, Valorant style; bots take what is left) → game; or PLAY ONLINE → party. `CG.Player(scene, idx, x, feetY, { agent, name, bot, device, id, owner })`. Device types in `src/input.js`: `kbA`, `kbB`, `kbAll`, `pad`, `touch`, `bot` (`src/bots.js` returns the same input state), `remote` (online teammate), `any` (keyboard + mouse + pad 0 + touch, used online). Ability keys: C/E/Shift/right click, H (kb1), O (kb2), Y/RB, SKILL button.

## HOLLOW (`hollow/`) — everything below this line is about this game; paths are relative to `hollow/`

## Conventions

- **No build step.** Plain `<script>` tags in `index.html`, everything on the global `GH` namespace. A new file must be added to `index.html` in dependency order. No ES modules, no `fetch` of local JSON. Art is loaded by Phaser's loader, so the game must be served over http (not opened as a file).
- **Data-driven.** Content lives in `data/*.js` (`GH.DATA.weapons`, `.enemies`, `.abilities`, `.rooms`). The HUD and the planned admin panel read these lists, so new content should need a data entry, not new code.
- **Resolution** is 1920×1080 internal, `Scale.FIT`. Tiles are 64 px. Rooms are defined in tile coordinates as rectangles (`data/rooms.js`).
- **Art**: AI sheets are 8×4 grids of 256 px (or 512 px) cells with the background removed (transparent PNG). Every art prompt must tell the image tool to remove the background; no magenta key colour. See `tools/prompts.md`. Raw sheets go in `assets/sheets/` (or `assets/`). `python tools/build_art.py` slices and aligns them into `assets/atlas/` — slicing ONLY: pixels are copied untouched at the sheet's own resolution, with no background removal, alpha clean-up or resizing (the user's sheets are already transparent; the game scales frames at draw time using the scales in the manifest) — and writes `data/art.gen.js`; `BootScene.preload` loads that list. `src/art/placeholders.js` draws any texture key that real art did not provide, so real art must reuse the same keys (`player`, `w_<id>`, `b_<id>`, `eb`, `flash`, `guns_held`, `fx_impact`, `fx_explosion`, `tiles`, `props`, `tile_plat`, `spikes`, `bench`). Re-run the build after adding or replacing a sheet. The held-gun sheet pivots each gun on its firing line; don't move the shoulder height without checking shots still hit low enemies.
- **Player physics** sits on an invisible zone (`player.phys`); the sprite is visual only. Don't scale physics sprites — Arcade resizes the body with them.
- Arcade collision callbacks don't guarantee argument order; use the `mover/terrain/other` helpers in `GameScene.setupColliders`.
- Destroying objects inside a physics callback: disable now, `destroy()` via `time.delayedCall(0, …)`.

## Current direction

Sword-first, Hollow Knight style, with parkour (pits in the floor, fast movement). `GH.CONFIG.GUNS` is `false`: no gun sprite, no shooting, no weapon pickups, no weapon HUD. Guns come back later by setting it to `true`. The hero comes from one 10×5 sheet (`assets/hero_sword.png` or `30_hero_sword.png`, 50 frames, always holding a sword); `build_hero()` in `tools/build_art.py` cuts it sprite by sprite (the AI does not keep an exact grid) and `HERO_LAYOUT` maps animations to (row, position-in-row); a regenerated sheet can have a different sprite count per row, so check the printed "sprites per row" and the layout after every new sheet. It falls back to the old 01/02 sheets if the hero sheet is missing. A sheet saved as `assets/hero_v2.png` (the "Hero v2" prompt in `tools/prompts.md`, small pixel-art hero with no glow effects, 8-frame run on row 1) wins over `hero_sword.png` and is cut with `HERO_LAYOUT_V2`; the manifest marks it `pixel: true` so the Player sets the texture filter to NEAREST. Ledges (`platforms` in rooms) are solid on every side, no drop-through; their hitbox is 40 px thick to match the painted ledge, so never stack one ledge directly above another. Physics runs one variable step per frame (`fixedStep: false`) — a fixed 120 Hz step made movement stutter.

## World, enemies, boss

- Rooms (`data/rooms.js`) link through `exits`; touching one restarts the Game scene with `{ room, at, carry }` (carry = hp, shards, abilities, collected, cache, benchRoom). The HUD is relaunched each time and drops its old listeners on shutdown. Rooms without a bench send you back to `benchRoom` on death; the save stores `room` (bench room) and `maxHp`, and the shard cache remembers its room.
- `crossing` → `hall` (Warden's Hall, through the doorway at the bottom of the crossing's right wall). `GH.Boss` (`src/entities/Boss.js`) wakes when the player passes `boss.wakeX`, the doorway is sealed until it dies, and it grants +1 max health; `collected` gets `boss:warden`. Its shockwaves are `scene.waves` (jump over them).
- Painted art from `assets/enemies_v2.png` (10×5, one enemy per row, cut with `cut_cells`) → `en_<type>` strips + `GH.DATA.art.enemies[type]` (scale, anims); `boss_warden_v2.png` rows are uneven, so `boss_sprites()` groups sprites by ground line → `boss_warden`, `boss_wave`. Animations are `<type>_<anim>` / `boss_<anim>`, made in Boot. New types: `brute` (club smash) and `vengefly` (chasing flyer). Enemy hitboxes are divided by the sprite scale.
- `assets/tiles_v2.png` came with a checkerboard painted in instead of transparency; `build_tiles_v2()` only uses the solid parts (tiles cut from their first fully solid row, straight middle ledge pieces), nothing is erased. The tiles are rectangles (squashed sheet) and are drawn 64×64.

## Fairness rules (design constraint)

Multiplayer will be server-authoritative. Admin panel is single-player or private-lobby host only, and any admin use flags the save so it is excluded from leaderboards.

## Run / test

`node server/dev-server.js` (from the project root) → http://localhost:8080/hollow/ (`?reset` wipes the save). PWA install only works over localhost/https.

When the browser pane is hidden, `requestAnimationFrame` stops; drive the game with `GH.game.loop.step(t)` and inject input through `GH.Touch.s` to test.
